This guide covers every package in the fleet configuration.  For each
tool you get: what it does, and a couple of examples so you can start
using it right away.

System foundations use stable nixpkgs.  User-facing Home Manager packages and
program overrides use unstable nixpkgs so developer tools receive current
language and platform support. The unstable package set is pinned to
[[https://github.com/NixOS/nixpkgs/commit/c043004d1c6985732bcc1cbc5a9c9aecbbb4e0f0][c043004d1c69]] in =flake.lock=.

* Build toolchain

** gcc
C/C++ compiler.  Used by Emacs to compile native modules (jinx, vterm).
#+begin_src sh
gcc -o hello hello.c
gcc -shared -fPIC -o module.so module.c   # build a shared library
#+end_src

** cmake
Cross-platform build system generator.
#+begin_src sh
cmake -B build -S .       # generate build files from CMakeLists.txt
cmake --build build       # compile the project
#+end_src

** pkg-config
Queries installed library flags for compilation.
#+begin_src sh
pkg-config --cflags --libs enchant-2   # print -I and -l flags for enchant
#+end_src

** enchant
Spell-checking meta-library.  Jinx (Emacs) compiles against it.  You
rarely call it directly. It is a compile-time dependency.

** meson / ninja
Modern build system pair.  Meson generates ninja files, ninja executes them.
#+begin_src sh
meson setup builddir
ninja -C builddir
#+end_src

** esbuild
Fast JavaScript and TypeScript bundler installed as a cross-platform fallback.
Projects should invoke the version locked by their package manager rather than
silently substituting this global executable in builds or CI.
#+begin_src sh
esbuild src/index.ts --bundle --outfile=dist/index.js
esbuild --version
#+end_src

* Languages & runtimes

** python3
#+begin_src sh
python3 -c "print('hello')"
python3 -m venv .venv && source .venv/bin/activate   # virtual environment
#+end_src

** uv
Python version, environment, dependency, and command manager.  Home Manager
supplies the executable while each project owns its =.python-version=,
=pyproject.toml=, and =uv.lock=.
#+begin_src sh
uv sync --locked               # create or update the project environment
uv run pytest                  # run a command in the locked environment
uv add requests                # add and lock a dependency
uv python install 3.14         # install a requested Python version
#+end_src

** nodejs
JavaScript runtime.  Also provides =npm=.
#+begin_src sh
node -e "console.log(42)"
npm init -y && npm install express
#+end_src

** bun
All-in-one JavaScript/TypeScript runtime, package manager, bundler,
and test runner.  Drop-in faster alternative to =node=/=npm= for many
projects, with native TypeScript and JSX execution.  Installed
cross-platform via =home/base.nix=.

#+begin_src sh
bun --version                  # check installed version
bun run script.ts              # run a TypeScript file directly
bun init                       # scaffold a new project
bun install                    # install dependencies (reads package.json)
bun add express                # add a runtime dependency
bun test                       # run the built-in test runner
bun build ./entry.ts --outdir ./dist   # bundle for production
#+end_src

** Rust toolchain (cargo, rustc, rustfmt, rust-analyzer)
Individual Rust components installed via Nix (=unstable.cargo=,
=unstable.rustc=, =unstable.rustfmt=, =unstable.rust-analyzer=) in
=home/base.nix=.  No =rustup= is used.
#+begin_src sh
cargo new hello && cd hello && cargo run   # create and run a project
cargo build --release                      # optimised build
rustfmt src/main.rs                        # format Rust code
#+end_src

** go
Go programming language.  Installed cross-platform via =home/base.nix=.
#+begin_src sh
go run main.go
go build -o app .
#+end_src

* Clojure ecosystem

** clojure
Clojure CLI (=clj= / =clojure=) with tools.deps.  Installed
cross-platform via =home/base.nix=.
#+begin_src sh
clj                            # start a REPL
clj -X:deps tree               # show dependency tree
clojure -M:test                # run tests via alias in deps.edn
#+end_src

** babashka
Fast Clojure scripting with no JVM startup.
#+begin_src sh
bb -e '(+ 1 2)'                                # quick expression
bb -e '(-> (slurp "data.json") (json/parse-string))'
bb script.clj                                  # run a file
#+end_src

** clj-kondo
Clojure linter / static analysis.
#+begin_src sh
clj-kondo --lint src/            # lint a directory
clj-kondo --lint - <<< "(defn f [x] x x)"   # lint from stdin
#+end_src

** leiningen
Clojure project automation and build tool.
#+begin_src sh
lein new app my-project          # scaffold a new Leiningen project
lein repl                        # start a REPL
lein test                        # run tests
lein uberjar                     # build a standalone JAR
#+end_src

** neil
Manage =deps.edn= aliases and dependencies.
#+begin_src sh
neil dep add cheshire/cheshire   # add a dependency to deps.edn
neil dep upgrade                 # bump all deps to latest
neil new scratch my-project      # scaffold a new project
#+end_src

** Practicalli deps.edn
Not a package, but a flake input.  The community =deps.edn= from
=practicalli/clojure-deps-edn= is symlinked to
=~/.config/clojure/deps.edn=.  It gives you dozens of ready-made
aliases:
#+begin_src sh
clj -M:repl/rebel              # rich REPL with Rebel Readline
clj -M:test/runner              # run tests
clj -X:project/create           # create a new project
#+end_src
Run =clj -A:deps -Stree= to see everything available.

** tailwindcss-language-server
Tailwind CSS class-name completion, hover docs and diagnostics.
Triggers in HTML, JSX/TSX, Vue and Svelte buffers when a Tailwind
config is detected up the directory tree.

** htmx-lsp
Completion and hover documentation for [[https://htmx.org][htmx]]
=hx-*= attributes inside HTML.  Tiny scope; expects to run alongside
=vscode-html-language-server= rather than replace it.

** docker-compose-language-service
Compose-file LSP shipped as the binary =docker-compose-langserver=.
Provides schema validation, completion and hover for service keys in
=compose.yaml= / =docker-compose.yml=.  Distinct from
=dockerfile-language-server= (which targets =Dockerfile= syntax) and
they coexist without conflict.

** marksman
Structural Markdown LSP: heading completion, =[[wiki-link]]= follow,
section rename across files, diagnostics for broken references.
Complementary to =ltex-ls=, which focuses on prose grammar and
spelling rather than document structure.

** vscode-langservers-extracted
The HTML, CSS, JSON, ESLint and Markdown servers extracted from VS
Code's source tree, packaged as a single Nix derivation that exposes
five binaries:
=vscode-html-language-server=, =vscode-css-language-server=,
=vscode-json-language-server=, =vscode-eslint-language-server= and
=vscode-markdown-language-server=.  Eglot / =lsp-mode= keys server
selection off the major mode, so each binary is picked up
independently.

** tofu-ls
The official OpenTofu language server.  It provides completion, hover,
diagnostics, formatting, symbols, and navigation for OpenTofu modules through
Emacs Eglot or =lsp-mode=.  It replaces the Terraform-specific language
servers because this fleet has no Terraform-only projects.

* Formatters and linters

** alejandra / statix / deadnix
The Nix formatting and static-analysis toolchain, installed cross-platform via
=home/base.nix=.  The tools have deliberately separate jobs: =alejandra=
formats source, =statix= reports Nix anti-patterns, and =deadnix= reports unused
bindings and arguments.

#+begin_src sh
alejandra .                     # format every Nix file below this directory
statix check                    # report Nix anti-patterns without changing files
deadnix                         # report unused Nix code without changing files
#+end_src

** black / isort / ruff

Python formatters and linter. Home Manager gives Ruff an =ALL=
stable-rule user fallback. Preview rules and unsafe fix-all remain
opt-in. A project's =pyproject.toml= (with =[tool.ruff]=), =ruff.toml=, or
=.ruff.toml= replaces the fallback; Ruff does not implicitly merge these
files. Use =extend= when inheritance is intentional. New stable rules
can appear after upgrades.

The fallback ignores contradictory docstring choices (=D203= and =D213=)
and formatter-owned indentation, quoting, and trailing-comma rules. It
retains annotation, security, correctness, complexity, modernization,
unused-code, and import-order checks. See [[https://docs.astral.sh/ruff/configuration/][Ruff configuration discovery]]
and [[https://docs.astral.sh/ruff/formatter/#conflicting-lint-rules][formatter rule conflicts]].

Emacs keeps isort followed by Black on save (=C-c r= on demand). Ruff
provides explicit import organization (=C-c l r o=), lint fixes, and
safe fix-all (=C-c l a a=). Organizing sorts imports; removing unused
imports is a separate fix. Ruff does not read =[tool.isort]= or
=[tool.black]=: projects that customize those tools should align their
Ruff options to avoid alternating changes. Overlapping unused-import
diagnostics from BasedPyright and Ruff are intentional; their
rule-specific suppressions are different (=pyright: ignore[...]= versus
=noqa: ...=).

#+begin_src sh
black myfile.py                # reformat Python
isort myfile.py                # sort imports
ruff check src/                # lint Python (very fast)
ruff check --fix src/          # apply safe lint fixes
ruff check --show-settings myfile.py # inspect effective rules and config
ruff format src/               # format Python (alternative to black)
#+end_src

** cljfmt
Clojure code formatter installed cross-platform through Home Manager.
#+begin_src sh
cljfmt fix src/                # format Clojure files in place
cljfmt check src/              # check without modifying
#+end_src

** yamlfmt / yamllint
#+begin_src sh
yamlfmt file.yaml              # auto-format YAML
yamllint -d relaxed file.yaml  # lint YAML
#+end_src

** shfmt / shellcheck
#+begin_src sh
shfmt -w script.sh             # format shell script in place
shellcheck script.sh           # lint shell script (catches quoting bugs, etc.)
#+end_src

** prettier
Formats HTML, CSS, JSON, Markdown, YAML, and more.
#+begin_src sh
prettier --write "**/*.json"
prettier --check .
#+end_src

* Testing

** bats
Shell test framework (Bash Automated Testing System). Tests live in
=tests/= and cover the =scripts/= activation snippets.
#+begin_src sh
bats tests/                                # run all test suites
bats tests/home-layout.bats               # run one file
bats --tap tests/                          # TAP-format output for CI
#+end_src

** ripgrep
Recursive regex search, faster than grep.
#+begin_src sh
rg "TODO" src/                 # search for TODO in src/
rg -t py "import os"           # search only Python files
rg -l "fixme"                  # list filenames only
#+end_src

** silver-searcher-ng (ag)
Maintained fork of Silver Searcher with PCRE2 support.  It provides the =ag=
command alongside ripgrep's =rg= command so programs can depend on either.
#+begin_src sh
ag "pattern" .
ag --clojure "defn"            # search only Clojure files
#+end_src

** fzf
Fuzzy finder.  Any list piped in becomes an interactive selector.
Configured in =home/base.nix= with =fd= as the file-listing backend so
=.gitignore= is respected and hidden files are included.

*** Shell key bindings (always available at the prompt)
| Key     | Action                                            |
|---------+---------------------------------------------------|
| =C-t=   | Paste selected file(s) onto the command line      |
| =C-r=   | Fuzzy-search shell history; =C-r= again for chronological order |
| =M-c=   | =cd= into a selected subdirectory                 |

*** Inside the fzf popup
| Key       | Action                          |
|-----------+---------------------------------|
| =C-a=     | Toggle-select all matches       |
| =C-/=     | Toggle preview pane             |
| =C-u=     | Scroll preview half-page up     |
| =C-d=     | Scroll preview half-page down   |
| =Alt-↑=   | Jump to top of preview          |
| =Alt-↓=   | Jump to bottom of preview       |
| =Tab=     | Mark/unmark one item            |

*** Worked examples
#+begin_src sh
# Open a file in $EDITOR, previewing it with bat before committing.
# Press C-/ to show/hide the preview pane.
$EDITOR $(fzf)

# Kill one or more processes interactively (multi-select with Tab).
kill -9 $(ps aux | fzf --multi | awk '{print $2}')

# Check out a git branch.
git checkout $(git branch -a | fzf)

# Replay a recent git commit as a patch to the working tree.
git show $(git log --oneline | fzf | awk '{print $1}') | git apply

# Fuzzy-grep then open the matching file at the right line.
rg --line-number '' | fzf --delimiter ':' --nth 1,3.. \
    --preview 'bat --color=always --highlight-line {2} {1}' \
  | awk -F: '{print "+"$2, $1}' | xargs $EDITOR

# Copy a selected file path to the clipboard (Wayland).
fzf | wl-copy

# fzf also works inside scripts: read one line from any list.
selected=$(printf '%s\n' alpha beta gamma | fzf)
#+end_src

** zoxide
Smarter =cd= that learns your most-visited directories.
#+begin_src sh
z nixos                        # jump to most-used dir matching "nixos"
zi                             # interactive selection

*** NixOS profile overrides

The local overlay in =config/firejail/firefox.profile= suppresses two
upstream directives that are incompatible with NixOS:

- =ignore private-bin=: the upstream profile restricts the binaries
  visible in the sandbox to a known list.  NixOS stores all binaries
  under =/nix/store=, which is outside the locations firejail searches,
  so the restriction breaks Firefox entirely.

- =ignore private-etc=: the upstream profile mounts a tmpfs over =/etc=
  populated with copies of the host files taken at sandbox startup.
  When NetworkManager updates =/etc/resolv.conf= after a WiFi network
  change, the stale copy inside the sandbox makes DNS resolution fail
  and Firefox loses internet access while all other applications
  continue to work.  Disabling this directive lets Firefox read the
  live =/etc/resolv.conf= directly.

Firefox relies on its own remote-instance mechanism for subsequent host-side
launches.  Firejail's =join-or-start= profile directive is intentionally not
used because it aborts before executing Firefox when the generated NixOS
wrapper supplies the executable after =--=.  Signal's =xdg-open= is replaced on
Signal's private =PATH= by an HTTP and HTTPS-only client for the desktop
=OpenURI= portal.  The portal launches the configured host browser, which
prevents a link click from starting Firefox inside the Signal sandbox or
bypassing the Firefox wrapper.

VS Code can write only to its configuration, extension directories,
=~/OSX-KVM=, =~/src=, and the canonical
=~/Dropbox (Maestral)/Example/src= path.  It also enables Firejail's packaged
hardened Electron include, which drops capabilities and adds =nonewprivs=,
protocol filtering, and seccomp while leaving development tools available.

** nh
Nix CLI helper that wraps =nixos-rebuild=, =darwin-rebuild=, and
=home-manager= with a nicer interface: a build tree via
=nix-output-monitor=, a coloured diff of what is about to change via
=dix=, and an interactive confirmation prompt before activation.

Installed fleet-wide via =home/base.nix=.  On linux-laptop the NixOS module
(=programs.nh= in =hosts/linux-laptop.nix=) also enables a weekly =nh clean=
systemd timer that prunes old generations (keeps 5, anything newer than

schedule (Sunday 03:00) via =hosts/macOS.nix=.

The =NH_FLAKE= session variable is intentionally unset: the flake path
is user-specific and must be supplied at the call site or via a personal
shell alias.  On linux-laptop, =NH_OS_FLAKE= is set automatically by the NixOS
module (=programs.nh.flake=) and takes precedence over =NH_FLAKE= for
=nh os= commands.

*** Seeing a human-friendly diff before switching

This is the key workflow: build the new configuration, show you exactly
what derivations and closures are added, changed, or removed, then ask
for confirmation before touching the running system.

On NixOS (linux-laptop):
#+begin_src sh
nh os switch          # reads NH_OS_FLAKE; auto-detects hostname
nh os switch -H linux-laptop   # explicit host
#+end_src

On macOS:
#+begin_src sh
nh darwin switch          # reads NH_FLAKE; auto-detects hostname
#+end_src

For Home Manager on any platform:
#+begin_src sh
nh home switch          # reads NH_FLAKE
#+end_src

In all three cases =nh= will:
1. Evaluate the flake and build the new system closure (output routed
   through =nix-output-monitor= for a readable build tree).
2. Display a =dix= diff: a compact, colour-coded summary of every
   package added, removed, or version-bumped between the current and
   new generation.
3. Ask =Apply? [y/N]= before running the activation script.

To preview without any risk of activation, use =--dry=:
#+begin_src sh
nh os switch --dry          # build + diff, never activate
nh darwin switch --dry
nh home switch --dry
#+end_src

** touchpad-watchdog (linux-laptop only)
The PixArt PIXA3854 I2C HID touchpad on the Framework 16 AMD 7040
sometimes enters a stuck state where the firmware sends only

both after suspend/resume and spontaneously during normal use.

** tor-transparent-proxy
Oneshot systemd service that installs nftables redirect rules capturing
all outbound TCP and DNS traffic through Tor.  Not started at boot; the
user toggles it manually.

IPv6 is blocked while the proxy is active because Tor does not support
IPv6 exit nodes (allowing it would leak traffic outside Tor).  LAN

LocalSend (port 53317) and mDNS continue to work.

#+begin_src sh
# Route all traffic through Tor

# Return to normal networking
sudo systemctl stop tor-transparent-proxy

# Check status
systemctl status tor-transparent-proxy

# Verify Tor is working
curl https://check.torproject.org/api/ip

# Verify the nftables table exists while active
sudo nft list tables
#+end_src

* ProtonVPN via NetworkManager (linux-laptop only)

linux-laptop uses NetworkManager (=networking.networkmanager.enable = true= in
=flake.nix=), which has native WireGuard support.  ProtonVPN connections
are imported at runtime as NetworkManager profiles rather than declared
in Nix.  Once imported, they appear in GNOME Settings > Network > VPN
and persist across reboots in
=/etc/NetworkManager/system-connections/=.

*** Downloading a WireGuard config

1. Log into [[https://account.protonvpn.com/downloads#wireguard-configuration][account.protonvpn.com]] > Downloads > WireGuard configuration.
2. Pick a country/server and platform (Linux).
3. Save the =.conf= file (e.g. =protonvpn-nl-42.conf=).

*** Importing and using the connection

#+begin_src sh
# Import the config as a NetworkManager connection
nmcli connection import type wireguard file protonvpn-nl-42.conf

# Prevent it from activating automatically at boot
nmcli connection modify protonvpn-nl-42 autoconnect no

# Connect
nmcli connection up protonvpn-nl-42

# Disconnect
nmcli connection down protonvpn-nl-42

# Check status
nmcli connection show --active

# Remove the connection entirely
nmcli connection delete protonvpn-nl-42
#+end_src

The connection can also be toggled from the GNOME network menu in the
top panel (the VPN toggle appears once at least one VPN connection is
imported).

*** DNS leak prevention

NetworkManager sets DNS servers from the WireGuard config automatically.
Verify that DNS queries go through the tunnel:
#+begin_src sh
resolvectl status           # check which DNS server is active per interface
resolvectl query example.com  # confirm resolution goes through the VPN DNS
#+end_src

If =systemd-resolved= is active (it is on linux-laptop), NetworkManager
routes DNS through the tunnel interface by default when the VPN
connection has =ipv4.dns-priority= set lower (more negative) than other
connections.  ProtonVPN configs ship with their own DNS servers so this
works out of the box.

*** Multiple servers

You can import several configs (different countries, different server
load) and switch between them:
#+begin_src sh
nmcli connection import type wireguard file protonvpn-ch-15.conf
nmcli connection modify protonvpn-ch-15 autoconnect no
nmcli connection down protonvpn-nl-42 && nmcli connection up protonvpn-ch-15
#+end_src

*** Interaction with the Tor transparent proxy

Do not run both at the same time.  The Tor transparent proxy captures
all outbound TCP/DNS at the nftables level, which would conflict with
the WireGuard tunnel.  Stop one before starting the other:
#+begin_src sh
# Switch from Tor to VPN
sudo systemctl stop tor-transparent-proxy
nmcli connection up protonvpn-nl-42

# Switch from VPN to Tor
nmcli connection down protonvpn-nl-42
sudo systemctl start tor-transparent-proxy
#+end_src

** middleclick (macOS only)
Synthesises a middle-click from a multi-finger trackpad tap so that
Firefox closes a tab on tap, Safari opens links in a background tab,
Terminal pastes the selection, etc.  macOS itself does not expose
three-finger tap as button 2, so a userland helper is required to get
the behaviour that NixOS gives for free via libinput.

Installed via Homebrew cask (=config/Brewfile=).  Configured to use a
*four*-finger tap rather than the upstream default of three, because
=system.defaults.trackpad.TrackpadThreeFingerDrag= is enabled in
=hosts/macOS.nix= and a three-finger tap would conflict with
three-finger drag.  The =fingers = 4= preference is written to
=art.ginzburg.MiddleClick= via =system.defaults.CustomUserPreferences=
in =hosts/macOS.nix=.

Autostart and menu bar visibility are handled through MiddleClick's
own UI rather than from Nix.  Both rely on macOS APIs (=SMAppService=
for login items and the status item autosave key for icon visibility)
that are not safely expressible as =defaults= writes, so the in-app
controls are the source of truth and persist across rebuilds.

One-time manual steps after the first =darwin-rebuild switch=:

1. Launch =/Applications/MiddleClick.app= once and grant
   Accessibility permission in System Settings → Privacy & Security
   → Accessibility.
2. From the MiddleClick menu, tick "Launch at login".  This
   registers a LaunchAgent under =~/Library/LaunchAgents/= via
   =SMAppService=.
3. Hide the menu bar icon: hold =⌘= and drag it off the menu bar
   until the ✖️ appears, then release.  The icon stays hidden across
   restarts.  To bring it back, open the app again while it is
   already running.

Other tunables (set with =defaults write art.ginzburg.MiddleClick …=
and restart the app):

| Key                | Default | Effect                                     |
|--------------------+---------+--------------------------------------------|
| =fingers=          | 3       | Number of fingers for the tap (we use 4)   |
| =allowMoreFingers= | false   | Accept taps with at least =fingers= fingers |
| =maxDistanceDelta= | 0.05    | Max cursor travel during the tap (0..1)    |
| =maxTimeDelta=     | 300     | Max touch-to-release interval, in ms       |
