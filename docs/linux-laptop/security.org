* Full disk encryption (LUKS + Btrfs)

The NVMe drive is partitioned with a 1 GB ESP and a LUKS2 encrypted
partition containing an LVM volume group.  The LVM holds a 72 GB swap
(for hibernate) and a Btrfs volume with subvolumes for root, home,
cache, and snapshots.

=allowDiscards = true= is set so TRIM passes through the encryption
layer.  This trades a small metadata leak (which blocks are free) for
SSD longevity and performance.  The trade-off is acceptable for a
personal laptop with reasonable physical security.

*Audit point:* verify that the LUKS passphrase has not been weakened
and that the encrypted device is the sole persistent storage.

* Secure Boot (lanzaboote)

Lanzaboote replaces =systemd-boot= and signs all boot components with
machine specific keys stored in =/etc/secureboot=.  Automatic key
generation and enrollment are enabled, including Microsoft keys for
firmware compatibility.

=kernel.kexec_load_disabled= is set directly (rather than through
=security.protectKernelImage=) because the latter also injects
=nohibernate= into kernel params, which conflicts with
suspend-then-hibernate.  Since swap is LUKS-encrypted, the hibernate
image is encrypted at rest and kexec remains blocked.

*Audit point:* run =sbctl verify= to confirm all boot files carry
valid signatures.  Check that the audit rule on =/etc/secureboot=
fires if keys are tampered with.

* Firewall and network stack

The shared firewall defaults to denying inbound traffic. LocalSend is installed
without opening inbound ports. Review the realised ruleset for any explicit
per-interface exceptions before enabling receiving services. NetworkManager manages
network connections. The SSH server and Avahi multicast discovery are disabled.

Kernel sysctls harden the network stack:

| Sysctl                              | Value | Purpose                                    |
|--------------------------------------+-------+--------------------------------------------|
| =net.ipv4.conf.*.rp_filter=         |     1 | Strict reverse path filtering              |
| =net.ipv4.conf.*.accept_redirects=  | false | Reject ICMP redirects (IPv4)               |
| =net.ipv6.conf.*.accept_redirects=  | false | Reject ICMP redirects (IPv6)               |
| =net.ipv4.conf.*.send_redirects=    | false | Never send ICMP redirects                  |
| =net.ipv4.conf.*.secure_redirects=  | false | Reject even "secure" redirects             |
| =net.ipv4.conf.*.log_martians=      |  true | Log packets with impossible source address |

*Audit point:* run =sudo nft list ruleset= and verify only the
expected chains exist.  Run =sysctl -a | grep redirect= and confirm
all redirect values are 0.

* Kernel hardening

| Sysctl / option                     | Value | Purpose                                   |
|--------------------------------------+-------+-------------------------------------------|
| =kernel.yama.ptrace_scope=          |     2 | Restrict ptrace to direct parent only     |
| =kernel.kptr_restrict=              |     2 | Hide kernel pointers from non-root        |
| =kernel.sysrq=                      |     0 | Disable Magic SysRq                       |
| =kernel.unprivileged_bpf_disabled=  |     1 | Block unprivileged BPF                    |
| =net.core.bpf_jit_harden=          |     2 | Harden BPF JIT                            |
| =kernel.dmesg_restrict=             |     1 | Restrict dmesg to CAP_SYSLOG              |
| =kernel.kexec_load_disabled=         |  true | Block kexec (protects Secure Boot chain) |

*Audit point:* run =sysctl kernel.yama.ptrace_scope= (and others)
after boot to confirm the runtime values match.

* Audit subsystem

The Linux kernel audit framework is enabled via =security.audit.enable=
and =security.auditd.enable=.  Rules log:

- Every =execve= call (catches unexpected binaries, reverse shells).
- Write/attribute changes to =/etc/shadow=, =/etc/passwd=, =/etc/group=.
- Write/attribute changes to =/etc/secureboot= (Secure Boot keys).
- Write/attribute changes to =/etc/sudoers= and =/etc/sudoers.d=.

Logs live in =/var/log/audit/audit.log= and are rotated automatically.

*Audit point:* run =sudo ausearch -k exec --start recent= to review
recent process executions.  Run =sudo aureport --summary= for a high
level overview.

* Crash and coredump capture

Three mechanisms ensure diagnostic data survives crashes:

1. *pstore:* on kernel panic the firmware writes the last dmesg to
   UEFI NVRAM.  =systemd-pstore= archives it to
   =/var/lib/systemd/pstore/= on the next boot.  The kernel parameter
   =printk.always_kmsg_dump=1= flushes the full ring buffer.

2. *systemd-coredump:* userspace crashes produce coredumps stored in
   =/var/lib/systemd/coredump/= (compressed, capped at 2 GB).
   Inspect with =coredumpctl list= and =coredumpctl info=.

3. *systemd journal:* persistent by default on NixOS 26.05.  All
   service failures, OOM kills, and kernel messages are journalled.

*Audit point:* after an unexpected reboot, check
=ls /var/lib/systemd/pstore/= for panic dumps, =coredumpctl list= for
userspace crashes, and =journalctl -b -1 -p err= for the previous
boot's errors.

* User and privilege model

- =users.mutableUsers = false=: passwords can only be set via
  =hashedPasswordFile= and =nixos-rebuild=.
- =security.sudo.execWheelOnly = true=: only wheel members can even
  execute the sudo binary.  The =btrbk= system user is added to
  =wheel= solely so it can execute sudo; its actual privileges remain
  limited to =btrfs=, =mkdir=, and =readlink= via NOPASSWD sudoers
  rules (set by the NixOS btrbk module).
- =nix.settings.trusted-users= contains only =root=. Regular users can
  request builds but cannot override daemon trust settings.
- =nix.settings.allowed-users = [ "@wheel" ]= restricts Nix daemon
  access to wheel members.

*Audit point:* run =getent group wheel= and verify only expected
users are listed.

* Application sandboxing (Firejail)

The VSCode profile explicitly permits =~/src=, =~/OSX-KVM=, its application
state directories, and the example canonical Dropbox source path. It includes
=electron-common-hardened.inc.profile= and =code.profile= for upstream
restrictions. These profiles and their effective permissions should be checked
against the installed Firejail version.

Firefox and Signal retain upstream application-directory whitelists and
sensitive-state blacklists. Firefox forwards links through its native
remote mechanism. Signal uses a restricted HTTP(S) portal bridge to open the
host browser. Other applications retain their separate filesystem profiles.

*Audit point:* run =firejail --list= and =firejail --tree= while the applications
are running. Verify both a cold launch and link opening into an existing
browser instance. Verify file selection through the desktop portal as well.

To permit another VSCode project path, edit =config/firejail/vscode.profile=
and add the appropriate =noblacklist= and =whitelist= entries.

* Service sandboxing (Maestral)

Both the Maestral daemon and the Maestral Qt tray icon run as systemd
user services with hardening directives:

| Directive                 | maestral | maestral-gui |
|---------------------------+----------+--------------|
| ProtectSystem             | full     | (none)       |
| PrivateTmp                | yes      | (none)       |
| NoNewPrivileges           | yes      | yes          |
| RestrictRealtime          | yes      | yes          |
| RestrictSUIDSGID          | yes      | yes          |
| ProtectKernelTunables     | yes      | yes          |
| ProtectKernelModules      | yes      | yes          |
| ProtectControlGroups      | yes      | yes          |
| SystemCallArchitectures   | native   | native       |

The GUI service has lighter restrictions because it needs DBus and
display server access.

*Audit point:* run =systemctl --user show maestral | grep -i protect=
to verify directives are active.

* Automatic updates

=system.autoUpgrade= is enabled with =persistent = true=.  If the
scheduled trigger at 04:00 is missed (laptop off, hibernated, or
suspended), systemd catches up on the next boot.

=allowReboot = false=: the system stages the new generation but does
not reboot.  Updates take effect at the next manual reboot or
=nixos-rebuild switch=.

*Audit point:* run =journalctl -u nixos-upgrade.service= to check the
last upgrade attempt and its outcome.

* Temporary files

=/tmp= is mounted as tmpfs (RAM backed).  All temporary files vanish
on reboot, preventing accidental persistence of secrets or cache.

Default size is 50 % of RAM.  For very large build artifacts, use
=~/tmp= on the Btrfs volume instead.

* Thunderbolt and USB4

=services.hardware.bolt.enable = true= activates the Bolt daemon.
GNOME prompts the user before authorising new Thunderbolt/USB4
devices, blocking rogue DMA attacks from freshly plugged peripherals.

*Audit point:* run =boltctl list= and review authorised devices.
Remove anything unexpected with =boltctl forget=.

* Bluetooth whitelist

The example leaves Bluetooth whitelist activation disabled. Set an
adapter address and complete device registry to opt in. Once enabled, its
activation script manages =/var/lib/bluetooth/=: only explicitly whitelisted
devices retain their pairing keys; other device entries are removed during
=nixos-rebuild switch=.

A defensive guard at the top of the sync script aborts if the adapter
directory path does not match the expected =/var/lib/bluetooth/XX:XX:XX:XX:XX:XX= pattern.

*Audit point:* after a rebuild, run
=ls /var/lib/bluetooth/<adapter>/= and verify only whitelisted MACs
remain.

* SSH client hardening

Home Manager configures SSH with:

- =IdentitiesOnly yes=: only the declared key is offered.
- =PasswordAuthentication no=: password fallback disabled.
- =HashKnownHosts yes=: host names in =known_hosts= are hashed.
- =StrictHostKeyChecking accept-new=: new hosts are accepted once,
  then pinned.
- =ForwardAgent no=: agent forwarding off by default.

*Audit point:* run =ssh -G github.com= and verify the settings match.

* Git supply chain verification

=transfer.fsckObjects=, =fetch.fsckObjects=, and
=receive.fsckObjects= are enabled.  The cleartext =git://= protocol
is blocked; only HTTPS and SSH are allowed.

*Audit point:* run =git config --global --get transfer.fsckObjects=.

* Btrfs snapshots as safety net

Hourly btrbk snapshots of =/home/example= into =/.snapshots/= provide
rollback for accidental deletions or destructive agent actions.
Retention: 24 hourly, 5 daily, 3 weekly.  The timer is persistent, so
missed snapshots are caught up on boot.

A failure alert writes a prominent message to all user-owned PTYs
and fires a GNOME desktop notification. It also sends an Emacs warning.

*Audit point:* run =sudo btrbk list latest= and verify snapshots are
recent.

* Considerations for periodic audits

** Flake inputs

Run =nix flake metadata= and review the dates of each input.  If any
are more than a month old, run =nix flake update= and rebuild.

** Firewall rules

Run =sudo nft list ruleset= and confirm no unexpected accept rules
crept in.

** Listening ports

Run =ss -tlnp= and =ss -ulnp= to verify nothing is listening that
should not be.

** Installed setuid binaries

Run =find /run/wrappers/bin -type f= and cross reference with
expected wrappers (sudo, polkit, etc.).

** Audit log review

Run =sudo aureport --summary= and =sudo ausearch -k exec --start today=.
Look for unexpected binaries or access to sensitive files.

** Coredump review

Run =coredumpctl list= and investigate any unexpected entries.

** Pstore review

Run =ls /var/lib/systemd/pstore/= after every unexpected reboot.

** Firejail check

Run =firejail --list= while VSCode is running to confirm it is
sandboxed.

** Nix store trust

Run =nix path-info --sigs /run/current-system= and verify signatures
come from your trusted keys.

** Snapshot freshness

Run =sudo btrbk list latest= and verify the most recent snapshot is
within the last two hours.
